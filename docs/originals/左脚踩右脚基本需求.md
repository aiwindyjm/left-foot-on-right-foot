# 左脚踩右脚

**中文名：左脚踩右脚**  
**英文暂定名：Left Foot on Right Foot**  
**项目定位：AI Agent 协作自动化 / Coding Agent Workflow / Experimental Open Source Project**

---

# 1. 项目概述

“左脚踩右脚”是一款实验性的开源 AI Agent 协作工具。

它解决的问题不是“如何让 AI 写更多代码”，而是：

> **如何消灭人在多个 AI Agent 之间反复复制、粘贴、切换窗口、点击发送、等待结果这一层机械工作。**

典型场景：

```text
人
 ↓
向 ChatGPT 描述目标
 ↓
ChatGPT 制定下一阶段任务
 ↓
复制 Prompt
 ↓
ZCODE / Codex / Claude Code 执行
 ↓
Agent 停止并输出执行报告
 ↓
人复制执行报告
 ↓
切回 ChatGPT
 ↓
粘贴
 ↓
ChatGPT 分析
 ↓
复制下一阶段 Prompt
 ↓
切回 Coding Agent
 ↓
粘贴
 ↓
点击发送
 ↓
继续执行
```

“左脚踩右脚”的目标是：

```text
ChatGPT / Supervisor
        ↕
   Left Foot on Right Foot
        ↕
ZCODE / Codex / Claude Code / OpenCode
```

让上述机械循环尽可能自动完成。

---

# 2. 名字的由来

“左脚踩右脚”来自一种中国早期武侠电视剧中非常经典的视觉想象。

武林高手施展轻功时，可以通过：

```text
左脚 → 踩右脚
右脚 → 再踩左脚
```

不断向上飞行。

从物理学角度看当然是不成立的。

但这种表现方式非常有意思：

> **通过一个看似不可能的动作，让自己突破原本的限制。**

本项目借用这个概念作为一种带有玩笑性质的技术隐喻。

现实中的问题是：

```text
Agent 停下来
↓
等人
↓
人拿结果给另一个 AI
↓
另一个 AI 给出新任务
↓
人再把任务送回去
```

我们希望做的是：

```text
Agent
 ↑ ↓
Agent
```

让 AI Agent 之间能够不断“踩着彼此往前走”。

所以：

> **左脚踩右脚，是一个故意有点荒诞、甚至违反直觉的 AI 自动化实验。**

这也是项目希望保持的气质：

**工程上严肃，名字上不正经。**

# 3. 项目背景

目前 AI Coding Agent 已经能够独立完成相当复杂的工作，例如：

- 阅读代码

- 修改代码

- 执行命令

- 调试

- 运行测试

- 检查 Git Diff

- 生成执行报告

- 根据上下文继续工作

但在复杂项目中，一个非常常见的工作方式依然是：

```text
人 → AI → 人 → AI → 人
```

尤其当一个 AI 负责“思考和规划”，另一个 Coding Agent 负责“现场执行”时：

```text
ChatGPT
   ↓
生成下一阶段任务
   ↓
人
   ↓
ZCODE / Codex
   ↓
执行
   ↓
人
   ↓
ChatGPT
```

真正占用人的往往并不是决策，而是：

> **把一个 AI 的输出搬运给另一个 AI。**

“左脚踩右脚”就是针对这一层提出的实验。

# 4. 核心理念

## 4.1 人类负责方向

人类负责：

- 项目目标

- 项目边界

- 关键决策

- 价值判断

- 最终批准

---

## 4.2 AI 负责规划

例如 ChatGPT 可以作为：

- Supervisor

- Architect

- Planner

- Researcher

- Reviewer

负责根据最新项目状态决定：

> 下一步应该做什么。

---

## 4.3 Coding Agent 负责执行

例如：

- ZCODE

- Codex

- Claude Code

- OpenCode

- 其他 Coding Agent

负责：

- 读取项目

- 修改文件

- 执行命令

- 测试

- Git 操作

- 返回真实结果

---

## 4.4 左脚踩右脚负责“搬运和调度”

它不负责代替人类做核心决策，也不负责重新发明 Coding Agent。

它负责：

```text
检测状态
 ↓
抓取结果
 ↓
传递结果
 ↓
等待 AI
 ↓
获取下一步任务
 ↓
回填 Agent
 ↓
继续执行
```

---

# 5. 产品目标

## MVP 目标

实现下面这一条完整闭环：

```text
ZCODE 执行
   ↓
ZCODE 停止等待输入
   ↓
自动获取执行报告
   ↓
自动发送给 ChatGPT Web
   ↓
等待 ChatGPT 完成分析
   ↓
自动读取 ChatGPT 回复
   ↓
识别下一阶段 Prompt
   ↓
自动发送回 ZCODE
   ↓
ZCODE 自动继续执行
```

整个过程中：

> **人不需要复制、粘贴、切窗口和点击发送。**

---

# 6. 非目标

第一阶段明确不做：

- 重新开发 Coding Agent

- 重新开发 ChatGPT

- 自动替用户做所有项目决策

- 强制绑定某一家 Coding Agent

- 强制绑定某一个模型

- 试图替代人工审批

- 第一版就做复杂的多 Agent 群聊

- 第一版就实现完整 Agent OS

项目首先只解决一个问题：

> **把人工搬运链路自动化。**

# 7. 用户故事

## 用户故事 A：Coding Agent 连续开发

作为开发者，我希望：

> ZCODE 执行完成以后，不需要我把执行结果复制给 ChatGPT。

系统自动把结果发给 ChatGPT。

然后 ChatGPT 给出下一步任务以后：

> 不需要我复制回 ZCODE。

系统自动让 ZCODE 继续执行。

---

## 用户故事 B：ChatGPT 负责项目总规划

作为项目负责人，我希望：

> ChatGPT 持续看到项目最新状态，并基于真实执行结果规划下一步。

而不是每一次都重新向它描述项目。

---

## 用户故事 C：出现重要决策时由人接管

作为项目负责人，我希望：

> 普通步骤自动执行，但真正需要我判断的时候自动暂停。

例如：

```text
HUMAN_GATE = true
```

系统弹出：

> “需要人工决策。”

# 9. 人类工作自动化边界

项目把人工工作拆成两类。

## 9.1 可以自动化的机械操作

```text
复制
粘贴
窗口切换
点击发送
等待生成
读取文本
回填 Prompt
再次发送
```

目标：

> 尽可能 100% 自动化。

---

## 9.2 不应该被自动化的判断

例如：

```text
是否改变产品方向
是否接受重大架构变化
是否删除重要数据
是否发布
是否提交高风险操作
是否终止当前任务
```

这些进入：

```text
Human Gate
```

---

# 10. Human Gate

系统允许 AI 自主循环，但不能无限制自主执行。

AI 可以返回：

```text
ACTION = CONTINUE
```

继续自动运行。

也可以返回：

```text
ACTION = HUMAN_GATE
```

暂停整个工作流。

例如：

```text
当前项目发现两种架构方案：

A：继续采用现有方案
B：重新设计核心模块

这将影响后续多个版本。

需要人工决策。
```

此时系统停止自动执行。

---

# 11. AI 输出协议

为了让系统能够稳定工作，不能依赖“猜 ChatGPT 在说什么”。

因此约定机器可识别的结构：

```text
<MORPHO_LOOP>

ACTION: CONTINUE

STAGE: phase-03

AGENT: zcode

PROMPT:
请继续执行第三阶段……

HUMAN_GATE: false

STOP_CONDITION:
完成第三阶段并通过 validate。

</MORPHO_LOOP>
```

也可以：

```text
<MORPHO_LOOP>

ACTION: HUMAN_GATE

REASON:
发现两种架构存在重大分歧，需要人工决策。

</MORPHO_LOOP>
```

# 15. 安全机制

必须默认：

```text
Human Gate
```

并对这些动作默认要求人工确认：

```text
删除文件
删除数据库
强制 Git 操作
发布生产环境
发送外部消息
涉及密钥
涉及账号权限
大规模修改
```

同时：

- 所有自动操作记录日志

- 所有 AI 决策保留原文

- 所有 Agent 输出可追溯

- 支持紧急停止

- 支持暂停自动循环

# 16. 可靠性原则

项目不应该依赖：

```text
sleep(30)
```

这种脆弱逻辑。

而应该优先判断真实状态：

```text
DOM 状态
UI Automation
进程状态
输出变化
Agent transcript
CLI event
```

原则：

> **能读取结构化状态，就不要截图；能使用 API，就不要模拟点击；必须模拟点击时，再使用 UI Automation。**

# 18. 成功标准

MVP 成功的唯一核心指标：

> **用户可以启动一次工作流，然后在没有人工复制粘贴的情况下完成多轮 ChatGPT ↔ Coding Agent 循环。**

例如连续完成：

```text
Round 1
ChatGPT → ZCODE

Round 2
ZCODE → ChatGPT
ChatGPT → ZCODE

Round 3
ZCODE → ChatGPT
ChatGPT → ZCODE

Round 4
ZCODE → ChatGPT
ChatGPT → ZCODE
```

期间：

```text
人工复制次数 = 0
人工粘贴次数 = 0
人工切窗口次数 = 0
```

直到：

```text
COMPLETED
```

或者：

```text
HUMAN_GATE
```

# 19. 项目定位

“左脚踩右脚”不是一个成熟商业产品。

它应该保持：

- 开源

- 实验性

- 搞怪

- 工程化

- 可扩展

- 欢迎各种奇怪想法

它首先是一个：

> **AI Agent 协作机制实验场。**

我们并不预设最终答案。

我们只是尝试验证一个问题：

> **如果把 AI Agent 之间原本由人承担的机械沟通成本拿掉，它们能不能形成更长、更连续的工作闭环？**
