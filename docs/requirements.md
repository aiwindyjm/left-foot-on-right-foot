## 已批准的具体取舍

以下记录初始化时的决定；后续监督层决策覆盖其中过时的角色与状态命名，原始记录保留用于追溯。

1. 正式名称统一为左脚踩右脚 / Left Foot on Right Foot；原稿中的 `MorphoLoop`
   和 `<MORPHO_LOOP>` 仅留作历史内容，不建立兼容解析器。
2. 通信采用严格 JSON，版本独立；不继续使用松散的冒号文本块。
3. 原稿 `CAPTURING_REPORT`、`SENDING_TO_LLM`、`PARSING_TASK`、`SENDING_TO_AGENT`
   分别统一为 `CAPTURE_REPORT`、`SEND_TO_LLM`、`PARSE_TASK`、`SEND_TO_AGENT`；
   增加 `PAUSED`，以区分人工暂停与错误、审批。
4. Human Gate 虽在原稿版本路线中列为第二阶段，但安全章节要求默认门禁。
   因此最低限度人工审批、停止、超时和防重复派发是 Phase 1 前置条件；
   Phase 2 扩展完整交互及恢复，不能借阶段划分取消安全约束。
5. Phase 0 没有可运行闭环。README 的“怎么跑”只介绍基础验证，不编造功能命令。
6. MIT、TypeScript/Node.js 24/npm、公有 GitHub 仓库与隐私提交邮箱已由维护者确认。

## 后续决策：本地模型监督层

2026-09-17，用户明确修正定位并确认：本地部署的大语言模型替代原来的人工协调者，
让外部规划 AI 继续规划，本地模型监督规划端与执行端协作；规划端不限于 ChatGPT。

- 取代旧设计中“系统只搬运”和“ZCODE ↔ ChatGPT Web 固定闭环”的假设。
- 本地监督者理解上下文、审查报告和候选任务，决定转交、要求规划修订、派发或停止求助。
- 独立规划端保留；本地监督者不变成替代规划 AI 的单一全能 Agent，不自主变更目标。
- Adapter 和程序仍承担 I/O、权限、限额、去重与停止，固定脚本不能替代模型的监督判断。
- 初期仍为单项目、一个规划端、一个执行 Agent；增加监督角色不是提前实施多 Agent 平台。
- 当时本地模型、硬件需求及推理服务未选定；后续具体默认方案见下方技术选型补充，TypeScript 仍只承担控制程序。
- 协议草案升级为 `0.2`，新增监督决定及规划/监督身份，旧 `0.1` 不再接受，见协议迁移说明。
- 本轮只修订 Phase 0 资产，不安装模型、不实现运行时，也不包含 Git 提交、推送或发布授权。
