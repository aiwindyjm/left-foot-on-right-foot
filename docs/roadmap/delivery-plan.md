# 落地开发计划：架构统筹，ZCODE长任务交付

日期：2026-09-20，修订2。依据 [PRD 1.6](../PRD.md)、[架构](../architecture.md)、
[技术栈](../tech-stack.md) 和 [桌面接入验收](../desktop-integration.md)。
状态：用户明确要求先开发功能；下一任务是批次A功能开发版，不再等待真实会话才能编码。
本修订覆盖此前“批次A接入证明、批次B才开发”的顺序，旧入场报告仅作历史，不作为当前入口限制。
它不证明功能已实现，也不授权读取聊天、控制电脑或发布。

## 1. 交付目标与当前事实

目标是用户装上桌面应用，绑定已有评估会话A与执行会话B，设置目标、PRD和停止百分比后，
正常轮次不再手工搬运。A评估和规划，B执行，本地模型理解并交接，程序检查权限、阈值和去重。
先交付Windows内测版，再通过Apple Silicon Mac实机验收。不为赶进度改成API新聊天或固定脚本。

计划编写时本地基线为 `06b5f6b`，工作区原本干净，`main` 相对本地远程跟踪记录领先1次提交。
此前推送失败；本次未重新查询远端或推送，远程现状不能仅凭跟踪记录断言。
已有文档、协议0.2、旧隔离评估工具和基础测试；没有桌面程序、生产Adapter、真实自动闭环或安装包。
基础测试数量不是产品完成度。协议0.2仍含旧独立监督审计语义，不能直接当新运行时设计。

| 落地成果 | 当前状态 | 完成证据 |
| --- | --- | --- |
| D0 需求与桌面架构基线 | 已有 | 现有PRD、技术栈、规则和接入清单 |

## 2. 分工：只保留一个开发交接入口

| 角色 | 职责 | 不转嫁给用户的工作 |
| --- | --- | --- |
| 用户/产品负责人 | 确定目标、测试对象、授权和重大取舍；体验最终产品 | 不拆编码任务，不收集各子Agent报告，不逐文件审计 |
| 本会话/项目经理与架构师 | 维护范围、依赖、技术边界；批次级PRD回归；提供下一整批收口指令 | 不逐个接手功能编码，不重复审核每个小提交 |
| ZCODE主会话/开发负责人 | 读取规范、拆解工作包、分配所有权、集成、自测、自审、修复及维护总报告 | 不把编译失败、常规测试失败和可自行解决的冲突逐次交回 |
| ZCODE子Agent/工作流 | 在限定工作区实现模块并交验证证据 | 只向主会话汇报，不直接要求用户搬运给架构师 |

本会话负责更新计划，不启动Agent；功能编码交给ZCODE。用户转交的ZCODE入场报告称支持子Agent与worktree，
执行者沿用已有核对结果，环境变化才复核，不反复进行同一套入场调查。无可靠隔离时由主会话顺序完成工作包，
保留长任务与自动测试，不要求用户手开许多窗口充当调度器。
架构师不会在用户未唤起时自动读取ZCODE或持续后台审计，目前也没有已实现的会话桥接。

## 3. 三个交付批次，不是每做一点就回来

| 批次 | 范围 | ZCODE内部持续工作 | 向架构师交接的时机 |
| --- | --- | --- | --- |
| A 功能开发版 | W2-W5、W6/W7本地部分 | 契约、核心、模型客户端、存储/调度、平台与产品适配、桌面、模拟集成及开发包 | 可运行功能和整批测试证据齐备，不能只交入场检查 |
| B Windows真实联调与内测 | W1、W6/W7真实部分，D1-D3 | 指定已有会话先读后写联调、修正产品差异、模型实测、真实闭环和安装验收 | Windows真实兼容与内测证据齐备，或关键路径受阻 |
| C Mac落地 | D4，W8 | 原生适配、产品差异、权限、模型性能、安装与共同场景回归 | Mac实机验收齐备，或出现平台路线取舍 |

当前先执行批次A，覆盖功能实现、普通测试和集成修复；W2契约冻结及模块完成是ZCODE内部检查点，
不需要逐个回传审批。真实会话、控制许可和模型运行额度尚未提供时继续做无关编码和模拟测试。
批次B真实只读与写入仍分开授权；真实控制不是一次笼统“开发功能”能够替代的许可。
工作包编号保留便于追踪，但不再按W1到W8数字串行；W1移至批次B，W6/W7按本地和真实验收拆开。
每次批次报告由架构师读取代码及证据，必要修复以一个缺口清单整体交回，不零散追加指令。
不承诺只需三次用户操作：账号登录、系统权限、真实风险及设备不可用仍可能需要人。

## 4. 工作包、依赖与出口

### W1：Windows真实接入联调（批次B，不是编码前置）

- 输入：批准的测试目录、Codex和ZCODE各自已有A/B、读取范围、工具链安装许可。
- 使用批次A已有Adapter及控制组件进行先读后写联调，必要时补诊断probe，按实测修正产品差异。
- 官方接口/事件优先，不能可靠复用已有会话才走UIA；不读取私有库，不换新会话，不用坐标兜底。
- 两产品分别证明真实项目/会话身份、当前轮次、长回复完整性、生成结束/权限等待/错误可区分。
- 另获授权后在无破坏性材料上测输入、发送回执、停止；前台读取也纳入获准操作范围。
- 出口：按接入清单提交PASS/FAIL/BLOCKED/NOT_RUN、版本、限制、复现步骤及脱敏证据。
- 失败：两产品分别报告；一个成功不代表首批全部成功。不擅自减少范围，向架构师提出选择供用户决定。

### W2：冻结最小共享契约与构建基础

- 批次A起点，由ZCODE主会话单一负责；不依赖W1、真实A/B、发送权限或模型加载。
- 从PRD FR-01至FR-22建立需求到工作包和验收证据的映射，P1明确后置，不用目录数计进展。
- 迁移AI协议和状态模型：理解本轮评分/原提示词/澄清/停止，移除生产路径中的独立重审计要求。
- 原生JSON-RPC独立版本化；确定产品会话能力、来源绑定、完整性、发送确认及未知结果的共同语义。
- 固定核心事件、持久化意图/回执、取消及UI IPC契约；模型不能生成任意原生操作参数。
- 复用strict TS、npm、Ajv与node:test，按选型落实项目依赖和锁文件；遵循执行环境安装权限。
- 系统SDK/提权/付费仍另行确认；个别依赖受限时记录局部阻塞，不把其他模块也停掉。
- 出口：可运行的契约测试、假Adapter/模型服务、构建命令和各工作区基线；没有空包作为交付。
- 旧评估工具保留可复现语义，按明确版本隔离；相关测试迁移需记录理由与等价覆盖，不能简单删断言使其变绿。

### W3：协调核心、本地模型与可靠记录

- 依赖W2；所有权为核心、Ollama连接及存储模块和对应单元测试。
- 完成目标/PRD版本、会话绑定、用户阈值、自然语言理解、原文引用、有限澄清、交接与停止。
- 本地模型只理解，不重评分；程序以当前来源和原文校验结果，发送原提示词而非模型改写版。
- SQLite单写入、意图先落库、回执关联、去重；存储失败不发送，未知发送及重启保持暂停。
- 多项目状态独立、真实目录/别名/重叠路径互斥、本地推理串行、前台队列公平且有期限。
- 单项目停止与全局停止独立于推理/原生阻塞；取消不假称撤销外部执行。
- 批次A出口：实现Ollama客户端、生产提取Prompt/Schema、引用校验及错误处理，以本地假服务验证真实调用代码，不能只有返回固定分数的桩。
- 确定性场景和故障注入通过；真实Ollama理解/延迟/资源在获准联调中验证，不恢复旧40题考试。

### W4：Windows原生控制与产品Adapter

- 依赖W2，不依赖W1实测；所有权为Windows helper和产品适配模块，不拥有核心调度和数据库。
- .NET10/FlaUI.UIA3封装版本化stdio能力；已有会话绑定、完整读取、结束检测和发送确认按产品实现。
- 一位所有者维护helper共用接口；Codex/ZCODE子工作可拆开，但不得并行改同一平台公共文件。
- 所有前台动作由核心队列授权，包含切换到确认全过程；身份改变/接管/权限撤销关闭新输入。
- 临时剪贴板按许可使用，保留用户新内容；helper异常和主进程失联不继续动作。
- 批次A出口：stdio传输、方法实现、权限/取消和失效处理代码；用自建测试控件程序或假传输测试，不接触用户应用。
- 产品Adapter完成请求路由、绑定/完整性/回执校验和可测交互逻辑；未知产品布局或接口行为标记待联调/不支持，禁止杜撰选择器与成功回执。
- 缺SDK可先写源码、TS客户端及契约测试，原生编译标记NOT_RUN；不能因此不做核心或桌面。
- 批次B再完成两产品真实验收；测试控件通过不代表Codex/ZCODE支持。

### W5：桌面交互与安全宿主

- 依赖W2；可与W3/W4并行，先接假服务，不伪装为真实支持。
- Electron/Forge + React/TypeScript/Vite；项目列表、目标/PRD、已有A/B绑定、各自阈值和预算。
- 进度、评估依据、缺项、权限、前台队列、单项目暂停、全局停止及外部停止结果分别显示。
- renderer隔离/沙箱、本地资源、受限preload、来源/参数校验；协调utility与helper隔离阻塞。
- 原生ABI与helper打包风险在此做小型构建验证，不等到最终安装时才发现SQLite不可加载。
- 出口：桌面模拟E2E覆盖正常、等待、错误、权限拒绝与停止；窗口缩放下无遮挡，可用中文操作。

### W6：集成循环（批次A本地，批次B真实）

- 依赖W3/W4/W5；主会话在集成工作区统一接线，不能只把三个分支摆在一起。
- 批次A先无账号全链路：实际桌面 → 实际核心/存储/队列 → 模拟会话及假模型服务；不是各模块分别自测或一页静态演示。
- 批次B按获准范围运行Ollama与真实A/B，分别验证Codex双会话、ZCODE双会话。
- 覆盖从目标/PRD开始和接续B已有报告，保留失败与缺项，缺总分自动问A，达到阈值不发附带任务。
- 模拟场景用65→77→80验证轮次；真实场景不伪造分数、不为凑轮次越过停止阈值。
- 批次A出口：能在应用中创建模拟项目、配置阈值、启动循环、观察进度/缺项、暂停/停止并查看持久记录；开发测试入口与真实模式明确隔离。
- 批次B出口为D2：真实正常交接不需人工复制，证据关联完整，主要异常路径已测。普通失败在批次内修复。

### W7：多项目、故障收口和Windows安装包

- 本地部分依赖W6本地集成，实测部分依赖W6真实闭环；不能用缺少真实会话阻塞开发包构建。
- 批次A先测模拟多项目、故障注入、数据库重启及打包；并行等待和互斥机制在W3已设计。
- 至少两个独立测试项目，分别60%/95%阈值；前台读写排队、模型串行、同目录别名冲突拒绝。
- 覆盖用户接管、焦点失配、剪贴板竞争、锁屏/休眠、helper崩溃、丢回执、存储失败和重启不重发。
- 无开发SDK环境测试自包含helper、Electron ABI下SQLite读写、中文/空格路径、安装后首次启动。
- 不把Ollama和权重悄悄装进包；明确外部运行前提，缺少服务时引导而非假启动成功。
- 批次A输出Windows开发包、本地路径/哈希及模拟启动步骤，标记真实适配NOT_RUN；工具链阻塞则交可启动开发环境并明确包未生成，不称全部完成。
- 批次B输出完成实测的Windows内测安装包、安装/使用说明、兼容矩阵和已知限制。
- 出口为D3：PRD P0 Windows范围逐项有证据，用户完成一次完整体验；未测环境明确NOT_RUN。
- 内测产物不是公开Release；证书、费用、上传分发、签名和正式发布另获批准。

### W8：Mac适配与最终双平台交付

- 依赖Windows主线稳定及Mac实机/系统版本/工具链/权限/测试A/B就绪；批次C另获批准。
- 复用核心、契约、UI；Swift AXUIElement/AXObserver实现原生层，按Mac实际布局调整产品Adapter。
- 依次核对辅助功能拒绝/授予/撤销、句柄失效、前台输入和停止，不能照搬Windows选择器。
- Apple Silicon实测模型资源和延迟，增加Mac目录语义、构建、SQLite ABI及安装验收。
- 两产品分别完成共同场景；编译通过不等于平台支持，公开签名/公证和费用不自动获准。
- 出口为D4：Mac内测产物及实机证据、更新兼容清单，Windows关键回归不退化。完成后停止，不进Phase 2。

## 5. 并行方式：先契约，再三个实施方向

```text
批次A：W2 共享契约/基线（主会话串行冻结，无真实会话前置）
          +---------+---------+
          W3核心    W4平台    W5桌面
          +---------+---------+
                    W6 本地完整功能集成
                    W7 模拟多项目/Windows开发包
                    |
批次B：W1 指定会话联调 → W6 真实闭环 → W7 Windows内测验收
                    |
批次C：             W8 Mac适配/实机
```

建议最多3个编码执行者加1个主会话；这是开发资源上限建议，不是产品设置。
按实际ZCODE配额、内存和隔离能力降低并发，不假定Agent数量越多越快。测试跟随所有者，不另建一队反复评审。
主会话维护根package.json/锁文件、公共协议、共享状态、CI及集成报告；子Agent仅提交依赖变更请求。
W2开始时登记实际模块路径与所有者，初次创建须有实现内容，不为分工提前造目录。

开发并行仅限经批准的独立Git worktree/分支：每个执行者独立文件目录，不在同一checkout同时写入。
分支、worktree创建和本地检查点提交须有相应许可；未明确时不自动提交或强行并行，主会话先串行编码。
一个集成者串行审查并合并，禁止子Agent改main、互相覆盖或同时操作共享Git元数据。
只合并明确属于该工作包的提交；不reset、clean或自动删worktree“收尾”。权限缺失时改为单执行者串行。
共享契约变更由主会话冻结版本、通知依赖方并一起回归；架构方向变更找架构师及用户，不由子Agent决定。

这只是开发本项目的组织方法，不增加产品首版“同一真实目录多执行者”能力。
各worktree的构建/本地测试可并行；真实桌面测试、模型资源密集测试和打包集成按资源预约串行。
若ZCODE开发会话本身运行在被测应用中，使用已指定的其他测试A/B，不能把开发主会话当测试目标。
Windows首轮在独立测试项目验证，不让尚未验证的本产品负责协调自身开发，也不控制当前开发会话。

## 6. 长任务如何不中途丢球

主会话在批次内持续执行“实现 → 本模块测试 → 集成测试 → 修复 → 更新证据”，不以写完文件作为结束。
一个子任务受阻时先推进不依赖它的开发工作，不能擅自扩大真实操作或延伸到下一批次。
缺测试目录/A/B、Mac设备、模型加载许可或系统SDK不是停止所有功能开发的理由。
同一根因两次有实质变化的修复仍失败，整理复现与尝试，避免无上限盲试；批次时间/费用预算同样有效。
限额是上限，不要求耗尽；秘密、错会话、未知发送和权限异常立即关闭相关动作。

ZCODE把本地进度与续接记录放在已忽略的 `.local/delivery/`，在实际工作开始时创建。
记录批次授权引用、基线、worktree/分支、所有者、完成/进行/阻塞、测试结果和下一安全步骤。
不存Cookie/Token，不把完整聊天粘进报告；测试绑定等必要私密数据只留获准本地范围。
上下文不足时先写续接记录；恢复先核对Git和未确认操作，不凭旧日志重发或自动恢复真实控制。
主会话/系统终止时不能保证自动续接；用户只需一次恢复指令，不必重新讲PRD或搬运历史。

只在批次完成或阻塞时生成一个可提交的脱敏交付文档，建议命名 `docs/delivery/batch-A.md` 等。
这是未来输出约定，本轮不创建空报告。报告包含：

- 批次/授权范围、测试基线提交及尚未提交差异、分支/worktree位置。
- PRD编号 → 实现 → 测试命令 → 结果 → 证据位置；实现、模拟、实机、安装分别列状态。

## 7. 验收与进度不走偏

每个W工作包只能标记未开始、进行中、阻塞、待验收、验收通过，不能以自称完成替代证据。
核心普通缺陷由ZCODE测试和自审收口；架构师在批次出口抽查实现与关键证据并回归PRD，而非逐文件重复测试。
交接、阈值、身份、去重、权限/停止、持久化及安装是产品最终必验项，不能因其他功能完成度高而略过。
批次A验收功能代码和本地运行，批次B验收真实应用行为；不把不同层次合成一个含糊“全部通过”。
若需要开发总体百分比，由架构师基于约定范围及证据给出并注明缺项，不用测试数、行数或Agent工时推算。
这里的里程碑验收不改变产品用户阈值规则，也不会让运行时本地模型重新成为项目审计师。

现有 `npm test`、`npm run validate` 必须继续通过。后续由主会话增加并记录真实可运行的核心/原生/桌面/打包命令，
不在本计划虚构未存在的npm脚本。无账号CI只证明对应模拟和构建范围，实机证据单列。
无依据跳过的P0、错误会话、重复派发、达标后继续、停止无效、秘密泄露均不能通过内测验收。
Windows可先验收，Mac未测时明确不支持；不能把此阶段性产物说成双平台全部完成。
