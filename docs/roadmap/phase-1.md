# Phase 1: ZCODE ↔ ChatGPT Web PoC

目标版本：v0.1.0。状态：未实现。

入口：Phase 0 验收完毕，人类批准隔离测试环境、任务边界、可外发数据和接入研究。
先调查 ZCODE 的实际版本、状态事件、报告来源和发送接口；
确认 ChatGPT Web 的当前使用约束、授权与可行传输方式。不预设隐藏 API 存在。
如果没有可接受接入方式，停止并请求决策，不绕过认证、验证码或平台限制。

范围：一个项目、一个 Agent、一个规划会话的有限循环，优先结构化接口。
实现最低限度人工批准、停止、超时、轮次/无进展限额、关联去重和本地派发审计。
启动时必须显式确定限额，未经批准不连续执行；不得把这些安全措施延后到 Phase 2。

验收：

- 至少三轮真实完整闭环，期间人工复制、粘贴、切窗口和点击发送次数均为零。
- 人工参与只用于预定审批或停止；有脱敏报告、状态证据和消息关联记录。
- 协议错误、身份错配、权限请求、超时和未知发送结果均停止派发。
- 重复消息不重复执行；高风险任务不因 `HUMAN_GATE:false` 获得授权。
- 正常完成可停止，紧急停止路径经过测试；未确认 Agent 停止时准确报告。
- Core、Adapter 契约与隔离端到端测试覆盖上述行为。

不做：完整持久恢复、多 Agent、其他厂商 Adapter、Dashboard、自动发布。
出口：维护者审查证据并批准发布或指出阻塞，然后停止，不自动进入 Phase 2。
