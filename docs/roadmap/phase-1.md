# Phase 1：桌面多项目双会话闭环

目标：v0.1.0内测能力；状态：未实现。先完成 [Phase 1A接入关卡](phase-1a.md)，不直接建壳。
规格见 [PRD 1.5](../PRD.md)、[技术栈3.0](../tech-stack.md)；完整步骤见 [桌面接入验收](../desktop-integration.md)。

## D2 桌面最小闭环

入口：用户指定的Windows Codex和ZCODE同应用双会话接入验证达到所需能力，获得实现与试跑范围授权。
先迁移AI协议/状态及定义独立原生RPC版本，再实现Electron/Forge、React/TS/Vite与共享协调核心。
桌面可配置项目、已有A/B、阈值与授权，显示进度、权限、队列和停止；CLI仅调试。
A负责回归与打分，本地模型理解/交接，B执行；不复活旧独立审计方案。
验证普通自动回传与阈值停止、澄清、失配、重复、未知发送、模型故障、存储失败及必要人类审批。

## D3 多项目与Windows内测安装包

每项目最多一个在途执行任务，至少两个项目后台等待可并行，共享一个前台操作队列与串行本地模型队列。
同真实文件夹不能借别名或跨产品重复配置并发写；未知派发/重启不能释放保护后重发。
专用自动操作模式明确开启；切换到回执完整过程互斥，需要切换的观察也排队。
用户接管、焦点变化、权限失效、剪贴板竞争及全局停止必须中断新输入，并如实说明外部状态。
分别验收Codex双会话、ZCODE双会话及多项目场景；不同项目阈值独立，达标即停，不为凑三轮继续。
Forge安装包包含自包含Windows helper，Electron ABI下数据库测试和无开发SDK环境启动通过。
状态置于应用数据目录，不写目标项目，不打包账号、权重、聊天和浏览器资料。

## D4 Mac适配与实机

Windows内测之后使用现有Apple Silicon Mac，先登记OS、Xcode/Swift、应用及模型版本。
实现Swift/AX组件，共用TS协调与产品契约，验证辅助功能授权/撤销、控件变化、前台/剪贴板及停止。
模型资源与性能重新测，不套Windows显存结论；编译通过不等于交互通过，不提前标支持。
Mac包的签名/权限身份需实测，公开签名公证及费用另行批准，不绕过系统保护。

## 共同边界与退出

首批不含任意应用控制、同项目多执行者、截图/OCR、视觉模型、浏览器扩展成品、自动更新或公开发布。
保留最小持久记录、底层Agent权限和异常停止，完整恢复在Phase 2。
完成哪一平台就报告哪一平台的实测与限制；失败保留现场，不伪称完整闭环或双平台均可用。
维护者验收、指定后续任务或发布决定后再推进，不能因版本目标自行提交、推送或购买证书。
