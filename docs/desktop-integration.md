# 桌面接入验证与交付清单

日期：2026-09-20；依据 [PRD 1.6](PRD.md)、[架构](architecture.md)、[技术栈](tech-stack.md)。
这是待执行的验收规范，不是测试报告。真实能力均未实测；先开发功能，再按本清单联调验收。
本页D编号保留为验收项，不再表示功能编码的串行入口；当前开发批次见 [开发计划](roadmap/delivery-plan.md)。

## 1. 已确认的范围

| 决策 | 当前基线 |
| --- | --- |

| 平台 | 双平台设计，先Windows 11 x64，再现有Apple Silicon Mac实机；Mac系统版本尚未提供 |

| 权限与分发 | 按需辅助功能/原生组件，可安装内测包；不默认管理员/录屏，不含公开签名费用授权 |

## 3. D1开始前需要的信息

由用户确认以下内容，真实标识只保存在获准的本地记录中，不提交公开仓库：

- 测试项目文件夹，以及Codex内评估/执行会话、ZCODE内评估/执行会话的可识别标识；不自行枚举全部聊天。
- 本轮允许读取哪些消息/控件，是否含隐私，是否只使用脱敏试验材料；用户先打开并登录目标应用。
- 起初只读；切项目/切会话也可能影响前台，需在专用操作时段明确批准后进行。
- 后续输入/发送时明确目标、测试文字、允许动作、预算、停止方式及是否允许临时剪贴板。
- SDK安装/依赖构建的许可；本机dotnet --list-sdks未列出SDK，不静默安装.NET或系统组件。
- Mac的实际系统版本、设备架构、工具链与对应应用版本；有设备不等于已获得远程访问或测试权限。

缺少具体会话时不默认读取当前对话；不向真实项目发送任意“试一下”任务。
只读验证不请求真实模型生成，不触发执行、改配置、Hook安装、创建会话或取消用户现有任务。

## 4. D1先只读再写入

### A. 官方能力和工具链

Codex先核对公开app-server与当前应用版本的能力：指定会话是否可读、工作区和回复如何关联，
桌面客户端与外部客户端的所有权/审批是否冲突。thread/resume、turn/start不是只读探测命令，不能直接调用验证。
若无法证明已有会话安全共用，记录原因，再验证系统控件路径，不另建API会话绕开验收。

ZCODE按官方Hooks/事件核对session_id、cwd和最后回复；当前官方说明项目Hook忽略、变更须新session，
所以不能为了事件采集改变已有会话。已有绑定能否观察仍须实测；Hook不等于新任务发送接口。
不反编译应用、不读私有聊天库、不导出Cookie、不启动无认证控制端口。

工具链仅记录可执行工具、SDK版本与构建能力，不把dotnet命令存在等同SDK存在。
可先实现原生组件与产品Adapter代码，并用受控测试程序验证；真实应用未知的身份/选择器/回执不能伪造。
只读probe属于真实联调手段，不再是唯一允许编写的代码。

### B. 指定会话只读验证

| 项目 | 必需证据 | 失败时 |
| --- | --- | --- |
| 项目定位 | 真实工作区与产品项目映射，非仅窗口标题 | 标记AMBIGUOUS/BLOCKED，不猜 |
| A/B区分 | 独立会话身份及当前选中会话证据，切换后可复核 | 禁止任何写入 |
| 回复读取 | 中文、多行、代码块、长回复与用户核对结果相符，无虚拟列表遗漏 | 标记INCOMPLETE，不把片段当全量 |
| 当前轮次 | 能区分旧回复、当前结果、流式未完成和重复事件 | 不能靠“静止几秒”宣布完成 |
| 生成状态 | 运行、完成、等待权限、失败及未知的可区分依据 | 未知则等待核对/暂停 |
| 控件可用性 | 可读、可写、需前台、需权限、不支持分别记录 | 不用坐标假装控件可用 |
| 生命周期 | 多窗口、应用重启后旧句柄失效，身份重新绑定 | 不沿用过期定位 |

若读取需要滚动/切换/展开，先取得对应前台许可；只读阶段不把“没有发送”当成可以任意操控界面。

### C. 获准的输入、发送和停止

先用用户确认的无破坏性测试文字，在指定空输入框验证多行/Unicode/长文本输入与预览；已有草稿不覆盖。
再在明确发送许可下单次发送，验证提交到目标会话的文字和对应回执，而非只检查点击返回成功。
测试过程中若权限弹窗出现，交给人决定，不能自动点允许。无法确认已发送则停止，不重复试发。
外部取消/停止能力也只对获准测试任务验证，区分禁止新派发、外部停止确认与仍可能运行。

前台焦点复核、用户接管/取消、输入中应用关闭、剪贴板被用户修改、发送后回执丢失必须覆盖。
受限桌面、UAC或权限不足标明限制，不默认管理员启动或绕过系统审批。

## 6. D2-D4共同验收

| 类别 | 场景及必须结果 |
| --- | --- |
| 可配置阈值 | 80%评估在60%阈值停、95%阈值继续，等于阈值停；无默认80%、不凑轮次 |
| 语义交接 | 分项100%不能替总体65%；含糊向A追问；发送原提示词，不重评分或擅改 |
| 多项目 | 两项目独立PRD/阈值/消息/审批/预算；不同项目结果不得互相应用 |
| 前台队列 | 等待可并行，完整切换到确认过程独占；前台观察同样排队，不长期占锁等生成 |
| 文件夹冲突 | 同路径、链接别名、不同产品指向同目录不能并发写；不明在途状态保持阻断 |
| 接管与取消 | 单项目暂停、全局停止、焦点异常、锁屏/休眠及权限撤销禁止新输入，不假称回滚 |
| 发送故障 | 重复回复不重复派发；未知回执、进程崩溃或存储失败不自动重放 |
| 剪贴板 | 支持的内容恢复、不支持的格式明示；用户修改后不覆盖、不记录剪贴板历史 |
| 界面兼容 | 中英文控件、多窗口、多显示器/缩放、长回复、应用更新后显式检测失配 |
| Electron安全 | 无任意shell的preload；来源/参数/导航校验，远程文本不可执行，helper退出不继续输入 |
| Windows安装 | 中文/空格路径，无开发SDK环境可启动自包含helper，Electron ABI下SQLite真实读写与重启 |
| Mac实机 | 辅助功能授予/拒绝/撤销、应用重启、窗口切换；真实Apple Silicon模型资源与延迟 |

不把UI自动化测试默认接到用户真实账号。先假服务/假控件契约，再按授权运行目标应用测试。
功能开发起须同步新AI契约、独立原生RPC版本、机器状态及正反例；0.2测试不覆盖上述行为。

## 7. 内测与停止条件

Windows内测包包含应用和匹配架构helper，不含用户配置、会话、模型权重或浏览器profile。
Mac编译通过不等于实机交互通过；安装签名/公证与系统权限身份另测，不能指导用户关闭系统保护代替验收。
公开签名证书、账号费用、Release和推送另行批准；首批不实现自动更新。

下一步是功能开发，不再因D1测试对象缺失停止全部工作。先交付可运行开发版和模拟集成结果。
进入D1真实联调时才需确认测试文件夹、各产品A/B及读取范围，再按许可开展前台和发送测试。
