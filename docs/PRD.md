## 1. 产品定义

左脚踩右脚是以本地模型为协调层的 Windows/macOS 桌面应用。
人可配置多个项目文件夹，每个项目选一个评估会话和一个执行会话，分别设置目标、PRD范围和停止条件；
系统在各项目内持续传递结果和下一轮提示词，直到对应项目达到停止条件。CLI保留作开发调试入口。

**充分信任用户选定的评估会话进行 PRD 回归、完成度判断、缺项分析和下一步规划。
本地模型不再重复承担这些项目审计职责，只接替人反复询问、理解回复、交接和看停止条件的工作。**

```text
人：目标 + PRD + 评估会话 A + 执行会话 B + 停止阈值
                          |
            左脚踩右脚：本地模型协调
                 /                  \
      A：核对进展、给完成度        B：执行提示词
         列缺项、给收口提示词         返回本轮结果
```

模型通过工具读取和发送；程序承担权限、绑定、限额及去重。“本地”只指协调模型在本机推理，不保证两端离线。
产品不是新的 Coding Agent，不是任意多 Agent 平台，也不是必须控制网页的 RPA 工具。
桌面UI可采用Web技术，但普通网页本身不是系统控制层；桌面宿主也不自动获得控制其他应用的权限。

## 2. 实际操作与会话配置

### 2.1 用户现在如何操作

1. 人确定目标，在一个执行会话中推进项目。
2. 执行端返回结果，人复制给另一个会话。
3. 人问：“你帮我核对一下目前项目与 PRD 的进展，按百分比评估完成度，列出缺损项目并给出收口计划及提示词。”
4. 评估会话给出完成度、缺项和下一轮提示词。
5. 人查看是否达到自己设定的停止条件；没达到就把提示词复制回执行会话。
6. 执行完成后，再重复上述操作。

产品要替代的是第 2 到第 6 步中的日常协调，不要求人每轮继续按发送，也不要求本地模型重做评估会话的工作。

### 2.2 会话是配置对象，不是品牌角色

| 配置场景 | 评估会话 A | 执行会话 B |
| --- | --- | --- |
| 跨产品 | ChatGPT 网页中的指定对话 | Codex 指定会话 |
| 同产品同项目 | Codex 项目内会话 A | 同项目内另一个会话 B |
| 其他组合 | Codex Work、普通对话、豆包、ZCODE 或其他有评估能力的会话 | 具备相应执行能力的指定会话 |

这些是需求场景，不是已支持清单。产品可在不同运行中承担不同角色，单次运行内角色固定。
同一产品、同一项目不等于同一会话：A 与 B 必须绑定不同会话，分别保留上下文；不自动创建新会话替代用户选择。
纯聊天端可以评估提供的资料；承担代码执行的会话必须确实具备工作区执行能力。
首批验收分别为Codex项目内双会话、ZCODE项目内双会话，沿用用户指定的外部应用已有会话。
跨产品仍为可扩展需求，不要求首批同时实现；不得为了接入方便静默改成API新聊天或替用户创建新会话。

## 3. 用户与范围

首要用户是已经习惯在两个 AI 会话之间复制报告和提示词的个人开发者。
MVP为单用户、多项目；每项目可登记多个会话，但每轮仅启用一评估、一执行。
不同项目的后台等待可并行，每项目最多一个在途执行任务；同一实际文件夹不能通过别名或重复配置并发写入。
双平台统一设计，先Windows 11 x64可安装内测版，再Apple Silicon Mac实机验收；Mac系统版本与工具链须在接入前记录。
默认后台操作；用户可显式开启专用自动操作模式，允许前台切换、输入、发送及临时剪贴板，所有前台动作共用一个队列。
检测到用户接管、焦点异常、身份不明即停止新输入；不声称能撤销已经发生的动作。
用户接受按需辅助功能权限和打包的原生组件，首版不申请录屏、不默认管理员运行、不绕过系统审批。
原开发机快照不构成最低硬件要求；不购买硬件、不关闭用户程序、不静默换模型。

## 4. 目标与非目标

| 编号 | 产品目标 | 判断方式 |
| --- | --- | --- |
| G-01 | 去掉正常循环中的人工搬运 | 初始化后，无人工复制、切换、粘贴和代发 |
| G-02 | 沿用用户信任的评估与规划会话 | 回归判断、百分比、缺项与提示词来自绑定 A |
| G-03 | 按完成度条件自动收口 | 未达标继续，达到或超过阈值停止新派发 |
| G-04 | 项目与会话组合可配置 | 多项目独立绑定/阈值，首批验证Codex及ZCODE各自双会话 |
| G-05 | 用户可控、交接可追溯 | 可停止，能查看本轮评估、发送对象及停止原因 |

非目标：让本地模型成为第三个项目审计师、自己设计需求权重评分系统、重做规划、直接写业务代码、无限自主运行。
不要求为双会话循环建设通用 Agent 工具平台、视觉控制、向量数据库或多服务架构。
桌面UI是正式入口，但须先验证接入；任意应用控制、同项目多执行者并发、OCR/视觉模型、浏览器扩展成品和自动更新不属于首批验收。

## 5. 职责与信任边界

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| 人 | 目标、PRD 范围、会话选择、阈值、运行授权和重大决定 | 正常轮次反复复制与点击发送 |
| 评估会话 A | 对照目标/PRD 核对进展、给总完成度、列缺项、给收口计划及可直接发送的提示词 | 扩大人的授权或以评分自动批准发布 |
| 执行会话 B | 执行收到的任务，返回结果、验证、未完成项与阻塞 | 用自己的“完成了”代替 A 的总体评估 |
| 本地协调模型 | 组织回归请求、理解回复、提取本轮总完成度与提示词、请求必要澄清、提出交接或停止动作 | 独立重打分、重做 PRD 审计、偷偷改写 A 的任务、替人批准高风险操作 |
| 程序与 Adapter | 绑定会话、读取发送、校验字段、比较阈值、权限/限额/去重、记录与停止 | 猜测消息来源或发送成功、绕过服务限制 |

正常情况下采用 A 的评估，不因本地模型另有技术偏好而启动第二轮项目审查。
读取的报告、提示词和评分不是权限凭证；信任回归能力不等于允许外部文字修改目标、路由或权限。
普通授权范围内交接自动进行；范围外及原有高风险动作仍找人批准。

## 7. 端到端流程与停止规则

### 7.1 一次设置

人提供目标与 PRD 引用/版本，选定 A/B，设置总完成度阈值和允许操作范围。
设置归属于具体项目；预检解析真实工作区，绑定产品实例与会话身份，不靠窗口标题识别。
登记多个项目不等于批准所有项目读写；逐项目确认会话范围、授权、预算和前台模式。
**停止百分比是每次运行的用户配置，例如 60%、80% 或 95%；80% 只是文档示例，不是固定值或默认值。**
未设置阈值时要求用户提供，不由模型擅自选一个。运行中用户可显式修改阈值，记录变更后重新判断；模型和两端会话不能自行修改。
同时确认时间、轮次、无进展及澄清次数上限；这些是异常保护，不是完成度算法。
会话标识须可准确定位，A 须能获得获准传递的 PRD 和执行结果；不能假称它已读过无权访问的仓库。
本地模型、读取、发送回执及停止能力通过相应接入检查后，才允许真实运行。

### 7.2 启动与正常循环

支持从目标和 PRD 开始：先请求 A 评估现状并生成第一轮提示词。
也支持接续 B 已有的一轮结果：先将该结果送给 A 回归。
不把“用户先手工写好 TASK JSON”作为产品使用前提。

```text
B 本轮执行结果
 -> 本地模型把结果连同固定目标/PRD范围交给 A，请求回归评估
 -> A 返回：本轮总完成度 + 缺损项目 + 收口计划 + 下一轮提示词
 -> 本地模型识别回复中的对应内容，程序检查本轮关联与阈值
 -> 达到阈值：停止新派发，输出评分、剩余缺项和停止原因
 -> 未达到：将 A 的执行提示词交给 B
 -> 等 B 执行结束，再回到循环开头
```

本地模型可在授权范围整理请求，但不得省略失败和未完成项，不修改 A 的执行提示词含义。
日常询问可采用下列模板，允许用户配置表达方式，不允许模板覆盖权限或目标：

> 请根据既定目标和本次 PRD 范围，核对以下执行结果与项目进展。给出本轮总体完成度（0 到 100%）及简要依据，列出缺损项目，再给出收口计划和一段可直接发给执行会话的提示词。请区分整个约定范围的完成度与单个任务的完成度，不要改变目标或扩大范围。

### 7.3 百分比的含义

- 百分比由绑定的 A 给出，针对约定目标/PRD 范围；它是 AI 评估，不是客观认证。
- 不以测试通过率、子任务进度、模型信心、执行轮次或 B 的自评分替代总体完成度。
- 不要求用户预先建立逐条需求权重；A 给出简要评估依据和缺项即可，评分算法不属于本地协调者职责。
- 总完成度及阈值均在 0 到 100 之间；比较规则为本轮有效总完成度 >= 阈值，可接受明确的小数。
- 取本轮完整回复的评估，不取历史最高分，不强制分数递增；保留原文与对应轮次。
- 分项分数、区间、矛盾总分或缺少总分不能猜成一个数，应请 A 明确本轮总完成度。
- 重复回复不算新进展；修改目标/PRD 范围后须重新评估，不沿用旧分数宣布达标。

### 7.4 继续、澄清与停止

| 情况（阈值为 80%） | 行为 |
| --- | --- |
| A 给出总体 65%，有明确执行提示词 | 自动交 B，执行后再询问 A |
| A 给出总体 79.9% | 尚未达标；有提示词且未触发其他停止条件时继续 |
| A 给出总体 80% 或 83%，也附提示词 | 达标停止，不再发送该提示词 |
| A 给出总体 80%，仍列出未做的 20% | 记录剩余项并停止，不要求补到 100% |
| A 没给总分、只给分项、总分冲突 | 在配置次数内向 A 澄清；仍不明确则暂停 |
| A 未达标但没给提示词，或只说“完成了” | 向 A 请求补充/核对，不由本地模型编任务或推断达标 |
| B 报告普通测试失败 | 如实交给 A 核对进展并给修复提示词，不另设本地代码审计 |
| 人要求停止、权限请求、硬限额、未知发送或连接故障 | 先禁止新派发，记录原因，不冒充达标 |

达到阈值是结束自动推进的充分业务条件，不需要为了“获准停止”再等待人工确认。
这不等于整个项目完成、最终验收通过或获得提交发布授权。人工验收可在循环停止之后进行。
显式安全门禁、在途状态不明不能被高分覆盖；停止新派发不等于强行关闭外部应用。
正常未达标时持续推进，而不是每轮找人确认；异常保护触发则暂停，不能无限追问或执行。

### 7.5 多项目与前台操作

每项目独立运行一条上述循环，共享一个串行本地推理队列和一个前台操作队列。
前台排队覆盖“切换应用/项目/会话 → 核对身份 → 输入 → 发送 → 确认”，不能只锁最后一次点击。
需要切换界面才能观察结果的读取同样排队；真正后台可读的等待不占前台队列。
普通前台操作完成即让出队列，不持有桌面等待模型生成；无法确认发送时暂停该项目，不能重复发。
单项目停止不影响其他已获准项目；全局停止禁止所有新派发和排队输入，在途外部任务停止结果分别显示。
锁屏、休眠、应用重启或权限撤销后先暂停受影响路径，重新核对绑定再由人恢复，不自动追赶队列。
剪贴板仅在允许的前台模式按需临时使用；保存/恢复支持的格式，不承诺无损恢复所有格式，用户修改后不覆盖恢复。

| FR-13 | 桌面状态和人工控制 | P0 | 项目列表、A/B选择、阈值、进度、权限、队列、单项目暂停及全局停止；CLI仅调试 |
| FR-14 | 不外发的场景验证 | P0 | 用模拟消息验证完整协调行为，不把考题数量当产品完成度 |
| FR-15 | 完整 Session 恢复 | P1 | 核对外部状态后继续，避免旧评估和不明发送被重放 |
| FR-16 | 历史与脱敏导出 | P1 | 用户控制保留和导出范围 |
| FR-17 | 更多会话产品接入 | 后续 | 同一契约按实际能力复用，不用产品名绑定角色 |
| FR-18 | 多项目调度 | P0 | 后台等待并行，前台队列单一拥有者，每项目最多一个在途执行任务 |
| FR-19 | 跨平台控制能力 | P0分平台交付 | Windows UIA与Mac AX共用能力契约，缺失能力显式报告，Mac不借Windows测试冒充通过 |
| FR-20 | 前台模式与剪贴板 | P0 | 显式开启/撤销，身份失配停止，剪贴板竞争不覆盖用户新内容 |
| FR-21 | 工作区互斥 | P0 | 真实目录别名/重复配置不能绕过单执行者限制 |
| FR-22 | 安装内测包 | P0分平台交付 | 无开发SDK机器可启动，原生组件可定位，打包无会话/秘密；公开签名另行批准 |

同项目多执行者并发依然非MVP，FR-18不授权多个Agent同时写同一文件夹。

## 9. 最小数据与记录

需要记录：项目及真实工作区身份、目标及 PRD 范围版本、A/B 绑定、停止阈值、授权与限额、本轮结果、A 的原始回复、
提取的总完成度及依据、缺项、下一轮原提示词、发送意图/回执、轮次与停止原因。
这些是产品概念，不是已经加入协议的新字段或可直接运行的配置格式。

连接提供来源绑定，模型不能凭回复里的名称选择新目标。只读取获准会话与必要任务资料。
桌面产品将配置、数据库和脱敏日志保存在应用数据目录，不写入被管理项目；既有开发评估的.local/保持不变，不自动迁移。
本地记录不进入 Git；外发遵守已批准范围，保留失败信息不等于无条件发送秘密或完整聊天历史。
普通会话可以回复自然语言，本地模型负责理解；内部结构化结果仍需校验，不能让用户承担 JSON 转换工作。
来源、完整性或语义有歧义时澄清或暂停，不从截断文本猜一个可执行任务。

## 10. 技术方向与实现边界

采用 [技术栈3.0](tech-stack.md)：Electron/Forge桌面宿主，React/TypeScript/Vite界面，TypeScript共享协调核心，
Ollama/Qwen3 8B初始模型，SQLite/better-sqlite3与Pino。Node24继续用于工程验证，Electron内置Node及原生ABI需另测。
Windows原生组件选C#/.NET10 + FlaUI.UIA3；Mac选Swift + AXUIElement/AXObserver。
宿主和原生组件通过版本化JSON-RPC标准输入输出通信，不开放无认证控制端口。
三层分别为项目与协调、产品会话、系统控制；模型仍只理解与交接，程序比较阈值，不新增独立审计层或通用Agent框架。
优先官方接口/事件，再控件操作，最后才在批准的前台模式中进行系统输入/剪贴板。
日常浏览器已有会话的后续路线为按需扩展+Native Messaging；Playwright用于专用受控环境，不默认接管日常浏览器。
首批分别验证Codex、ZCODE同应用双会话；公开接口存在不等于安全接管正在运行的桌面会话已获验证。
UI只加载本地内容，启用隔离/沙箱，有限IPC不暴露任意shell；先接入验证，再实现界面与闭环。

## 11. 协议与工作流衔接

产品流程为：配置 → 请求/接收 A 的评估 → 识别本轮总分 → 判断停止 → 未达标则交 B → 读取 B 结果 → 回传 A。
任何阶段都可因用户停止、门禁、故障或预算到限暂停。

[协议草案 0.2](../protocol/README.md) 与 [工作流 0.2](workflow.md) 尚保留旧审查设计，
其 Schema、机器状态表及评估代码在本轮不变，不能宣称已支持阈值、多项目队列或原生组件RPC。
原生RPC与AI消息协议分别版本化；桌面IPC同样校验来源和参数，不因为在本机就默认可信。
实施须同步协议版本、字段、自然语言到内部消息的边界、状态模型及正反例测试；
不得用旧 COMPLETED 冒充“已达 80%”。需区分达标停止、项目全部完成、用户取消、异常暂停和等待批准。

## 12. 异常与恢复

缺少评分或提示词属于协调澄清，不是立即让人搬运的理由；澄清有次数与期限限制。
本地模型不可用、身份错配、响应截断、结果不明、存储失败或账号失效时停止新派发并说明原因。
未知发送不改 ID 重发。恢复前核对已发内容和在途状态；MVP 不宣称自动恢复，重启默认暂停。
重复回评、无进展和评分倒退保留真实记录；按用户预设限额暂停，不能改阈值凑达标。

## 13. 授权与安全

启动时可批准向 A/B 发送指定范围内的资料和任务，不要求每条普通消息重新批准。
删除数据、Git 提交推送/强制操作、发布、费用、账号权限、密钥访问和重大方向变更仍需相应明确授权。
人可随时暂停或停止，底层执行工具权限不取消。本地模型不能自行批准操作或扩展范围。
未经许可不读取其他会话、账号文件、Cookie 或浏览器资料，不绕过产品使用限制。
“信任 A 的评估”不意味着所有聊天文字都是系统指令；门禁、路由和预算不能被提示词撤销。
公开资料不得包含真实秘密，安全报告见 [SECURITY](../SECURITY.md)。

## 14. 非功能要求

优先简单、可观察，非自动操作模式不干扰桌面；专用模式明确显示正在控制哪个项目/应用，可随时接管。
状态说明在等哪个会话、当前评分及为何继续/停止；多项目不能共享一个含糊的“运行中”状态。
推理、接入和发送有期限；停止入口独立于模型生成。模型故障无静默替代。
性能与资源实测后报告，不以旧保守显存预检推定用户机器无法完成产品目标。
贡献者无需真实账号即可运行基础测试；实测兼容清单与未支持能力分开公布。

## 15. 成功指标与验收案例

第一指标是减少真实人工交接，其次是正确使用 A 的评估与停止条件，不以独立审查题库分数替代。
下表未另外注明时使用80%作为测试示例阈值；产品不预设该值。

| 场景 | 验收要求 |
| --- | --- |
| 65% → 77% → 80%，阈值 80% | 前两次交接，第三次停止，无人工搬运 |
| 首次即评估 83% | 不派发首轮任务，输出达标停止报告 |
| 同样评估 80%，阈值分别设 60% 和 95% | 前者停止，后者有提示词且获准时继续，证明阈值未写死 |
| 未配置阈值或配置超出0到100 | 要求用户补充或修正，不静默使用80% |
| 用户显式修改阈值 | 留记录并按新阈值判断；会话回复不能代替用户修改配置 |
| 79.9% 与 80% | 边界比较准确，不取整提前停止 |
| 总体 65%，子任务 100% | 依据 65% 继续，不误判达标 |
| 历史 85%，变更范围后的本轮 70% | 使用当前目标与轮次评分，不取历史最高值 |
| 缺总分、区间或矛盾分数 | 向 A 澄清，仍不明确按限额暂停 |
| 达标且附带新提示词 | 不执行附带任务，记录未完成项即可 |
| 普通失败结果 | 交 A 评估并规划修复，不先做本地完整代码审计 |
| 同产品同项目两个会话 | 发送方向正确，A 不自回环，B 不冒充评估端 |
| 重复结果、未知发送、停止/权限请求 | 不重复执行，不因高分继续或声称外部已停止 |
| 两项目分别设60%和95%，均收到80% | 第一个停止，第二个继续；结果与阈值不串项目 |
| 两项目均需前台发送 | 前台完整操作事务串行，后台等待继续，不抢焦点 |
| 同目录别名或Codex/ZCODE重复绑定同目录 | 不能绕过单执行者约束，存在歧义先拒绝启动 |
| 用户接管、焦点改变、剪贴板被修改 | 停止新输入，不覆盖用户新内容，不声称已回滚动作 |
| 中英文控件、多窗口、缩放、多显示器、长回复、应用升级 | 可靠绑定与完整读取，失配显式失败，禁止固定坐标蒙混通过 |
| Mac辅助功能拒绝/撤销及应用重启 | 原生权限/句柄重新核对，不用Windows成绩代替Mac实测 |

记录人工介入、交接次数、阈值执行结果、澄清次数、耗时和故障，不编造节省比例。
真实场景未跑通时只报告模拟结果；正常达标不足三轮也必须停止，不能为凑三轮验收继续派发。
需要验证多轮能力时，使用获准且实际需要多轮的场景，不能伪造真实评估分数。

## 16. 验证与授权顺序

按已批准顺序执行：文档同步 → 用户指定Windows会话的先读后写接入验证 → 桌面最小闭环 → 多项目调度/Windows内测包 → Mac适配与实机验收。
不外发的协议/协调样例验证可在相应实现阶段先行，但不能跳过真实接入证据直接开发整个桌面产品。
具体检查、证据与授权门槛见 [桌面接入验收](desktop-integration.md)。
保留必要的权限、去重、异常及模型能力测试，但旧 40 题/重复三次的独立审查考试不是本版产品定义。
已有评估工具保留为辅助资产；如何复用由后续实施任务决定，本轮不删除、不重跑真实模型。
影子观察可用于接入验证，但不算自动交接交付；真实读写、预算和试跑仍需明确授权。

## 18. MVP 完成定义

- 桌面界面能管理多项目，各自设置目标、PRD范围、A/B、阈值和授权；CLI仅开发辅助。
- Windows上分别跑通Codex与ZCODE同应用双会话，跨应用不是首批前置；未实测组合不列为已支持。
- 多项目等待并行、前台输入互斥、同目录冲突保护、权限和剪贴板竞争测试通过。
- 本地模型完成回复理解与交接，A 负责回归评估及规划，B 负责执行。
- 正常范围内自动回传和交接，达到阈值停止新派发，无额外手工搬运。
- 含糊评分、提示词缺失、重复消息、异常和人工停止按规范处理。
- 展示最后评分及依据、剩余缺项、发送记录与停止原因，不把部分完成冒充全部完成。
- README 有真实配置运行方式及兼容限制；必要安全、测试和人工产品验收完成。
- Windows内测安装包通过安装运行验证；Mac作为后续平台单独报告构建及实机结果，不提前宣称支持。

## 19. 待实施确认与风险

核心流程和百分比来源已明确，不再要求用户重复解释人工操作。
首批产品组合已确定；剩余事项为用户指定的测试文件夹及A/B会话、读取/发送授权、SDK准备、Mac系统版本、
可用接入及使用约束、回复绑定、模型效果、协议迁移和预算。安装/公开签名账号与费用不自动批准。
这些问题不能反过来改变“信任 A 回归、本地模型协调”的职责。

主要风险包括 A 的评分偏乐观、上下文遗漏、接入不稳定、误提取子任务分数和未知发送导致重复执行。
处理方式是保留原文依据、固定目标/轮次、含糊时澄清、受控发送和异常暂停，不是再加本地项目审计层。
AI 评分不保证客观准确，达到阈值不保证质量或可发布；人保留最终价值判断和验收。
