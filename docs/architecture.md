# 架构设计

修订：3.1；日期：2026-09-20；依据 [PRD 1.6](PRD.md) 与 [技术栈](tech-stack.md)。
仅完成设计，未实现桌面程序、原生组件、项目队列或生产Adapter。旧评估代码和协议保留，不冒充新能力。

## 核心关系

每个项目启用一对已有会话：A回归PRD、给总分/缺项/提示词，B执行。本地模型理解、追问和交接，不重新审计。
用户按项目设置阈值，普通获准循环自动推进，达到阈值停止新任务，不代表项目100%完成或批准发布。

```text
Electron / React 桌面控制台
  项目列表、A/B、各项目阈值、前台模式、权限、全局停止
                      |
          有限preload IPC / Electron main
                      |
       TypeScript协调核心（独立utility进程）
  项目循环 + 共享模型队列 + 前台队列 + 权限/记录
          |               |                 |
       Ollama           SQLite       产品会话Adapter
                                      Codex / ZCODE
                                       /         \
                           官方接口/事件      系统控件能力
                                              /       \
                                      Windows helper  Mac helper
                                       C# / UIA3     Swift / AX
```

多个项目后台等待并行不等于同时操作同一鼠标；后台可读的状态不占前台，
需要切换会话/窗口的读取也必须排队。每个真实工作区最多一个在途执行任务。

## 三层边界

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 项目与协调 | 项目/目标/PRD/阈值/角色、轮次、权限、去重、工作区互斥、模型与前台队列 | 厂商控件选择器、平台句柄、重评分 |
| 产品会话 | 产品项目导航、真实会话绑定、消息完整性、生成状态、发送回执、停止能力 | 审批自己的任务或直接绕过前台锁 |
| 系统控制 | 控件查询/属性/动作、聚焦、输入、权限、受控剪贴板 | 理解PRD、选择哪个项目执行、任意shell |

同一Codex Adapter可绑定多个项目会话，ZCODE亦然；不要把A/B分别写成两个品牌分支。
Windows和Mac实现共同系统能力语义，但不假定控件树、快捷键或后台可写能力相同。
能力返回后台可用、需前台、不支持、权限不足或结果未知，不能假装成功填补缺失方法。

## 进程与模块

桌面renderer只显示本地UI，通过受限preload调用main；main管理窗口、权限入口、helper生命周期和停止信号。
协调utility进程持有业务状态和SQLite单写入者，平台helper隔离可能阻塞的原生调用。
模型在独立Ollama中运行；取消本地请求、杀helper均不等于外部Agent已经停止。

未来真实代码边界为桌面入口、可测试TS核心、产品连接器及Windows/Mac原生组件；
不提前建空包，CLI调试入口复用同一核心而不是另建调度器。
配置、数据库及日志置于Electron应用数据目录，不侵入被管理项目；旧开发.local/不自动迁移。

renderer无Node权限，只加载本地资源，导航和IPC来源均验证。
原生JSON-RPC经子进程stdio，版本握手、请求关联、期限和方法白名单独立于AI消息协议；
模型输出不能选择RPC方法或系统函数，UI也不拥有任意文件/进程执行入口。

## 绑定与完整性

绑定包含项目真实目录身份、产品/连接实例、会话身份及当次可核对证据。
路径别名、目录链接和重复配置归并到同一工作区锁；不同OS按实际文件系统语义处理大小写。
重叠工作区无法证明写入隔离则拒绝并发。评估A不因能编码就获得写工作区职责，底层权限仍保留。

不能仅凭窗口标题、点击返回成功或文本稳定几秒推定正确会话、发送确认和生成结束。
产品层结合官方ID/事件或经过实测的控件证据；找不到可靠身份或只读到虚拟列表片段则停止并报告。
应用重启、窗口/控件更新或焦点改变后，废弃旧句柄并核对绑定，不继续使用旧坐标。
用户选择已有会话，不能为配合API或Hook另建会话；只访问指定范围，不扫描全部历史。

## 每项目循环

1. 读取B完整结果，或将已批准目标/PRD交A作初始回归。
2. A给本轮总完成度、缺项、收口计划及提示词，本地模型识别原文与引用。
3. 含糊总分/任务向A有限澄清，不由本地模型编造；程序核对当前目标、轮次、权限和阈值。
4. 达到该项目阈值停止新派发，即使有后续提示词也不发；不影响其他项目。
5. 未达标则申请所需资源，保存派发意图，再将A的原提示词交B，记录确认。
6. B执行时释放前台资源；继续后台等待，未知发送不重试，异常暂停并保留状态。

不取子任务或历史最高分，不要求用户手写TASK JSON。
AI输出先成为受约束的理解结果，再经确定性检查，不重建独立reviewPlan/reviewReport审计关卡。

## 并发与前台模式

每项目最多一个在途执行任务，本地模型队列先串行；前台队列在同一用户桌面仅有一个拥有者。
完整前台单元为切换、核对身份、输入、发送、确认，任何需要切换界面的观察也通过队列。
采用公平排队及每操作期限，不能拿着前台锁等待整段模型生成；背景可读路径不强制抢焦点。
应用单实例与helper生命周期避免两个宿主分别调度；数据库未知派发与目录锁在重启后仍需核对。

专用自动操作模式显式开启，可见当前控制对象。非该模式禁止前台副作用，队列显示等待授权。
用户接管、焦点异常、锁屏/休眠或控制权限丢失时立即禁止新输入，当前结果记录为确认或未知。
检测不是撤销保证：已发生的点击不能宣称已回滚。恢复需核对后由用户操作，不自动补发排队旧内容。

临时剪贴板只在获准模式中使用，快照限支持的格式且仅存内存，写入后检查是否仍为本次值。
用户修改后不覆盖恢复；不能可靠保存的内容先暂停/提示，不声称所有格式无损。
不记录剪贴板历史、不全局监听键盘文字，不提前申请屏幕捕获权限。

单项目暂停关闭自身派发；全局停止关闭所有新发送和前台队列，撤销待执行请求并尝试取消在途操作。
停止结果区分“已禁止新派发”“外部停止已确认”“外部可能仍运行”，不能统一显示已停。
helper超时/退出不触发自动重发；主进程和协调进程失联时原生组件不得继续接受已失效动作。

## 实现顺序和契约迁移

顺序：契约与功能开发 → 模拟集成及开发包 → Windows已有会话联调/内测 → Mac适配与实机。
核心、桌面、平台组件与产品适配代码不以真实A/B就绪为前提；通过假服务、受控测试控件和契约测试持续验证。
平台未知行为留明确边界，不能凭猜测补上成功路径；真实接入证据是产品兼容验收条件，不是全部编码的前置条件。
具体证据与分步权限见 [桌面接入验收](desktop-integration.md)。
官方接口优先，Codex app-server共享已有桌面会话和ZCODE Hooks已有会话可用性均仍待验证。
首批Windows分别验证两种同应用组合；跨应用、浏览器扩展、视觉兜底和同项目多执行者后置。

[协议0.2](../protocol/README.md) 与 [机器状态规范](workflow.md)仍是旧静态契约，不含桌面RPC、全局队列或全部阈值能力。
实施时同步协议版本、Schema、样例、机器状态和测试；原生RPC另行版本化，不硬塞进旧DECISION。
本次只修正规范；后续由ZCODE实现功能及契约迁移，不以旧D0限制停止编码。真实操作和发布另按权限执行。
