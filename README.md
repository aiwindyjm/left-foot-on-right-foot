# 左脚踩右脚

**Left Foot on Right Foot**

> Let AI step on AI. 让 AI 踩着 AI 往前走。

**当前已确定Windows/macOS桌面方案，正落实文档与接入验收基线。已有基础和旧隔离评估工具，但桌面应用、安装包、自动交接与阈值停止尚未实现；尚无已验证的生产 Adapter。**

## 这是干什么的？

一个会话干活，另一个会话核对进展、出下一轮提示词。聊完以后，它们一起等你。

你复制报告、切窗口、粘贴、发送；等下一条 Prompt，再把刚才的动作倒着来一遍。
半天过去，代码是 AI 写的，快递是你送的。

这个项目想接过的，就是下面这套来回操作。你定好目标和 PRD，选两个会话，
再设一个停止条件，比如“完成度达到 80% 就停”。**停止百分比可以配置，80% 只是示例，不是固定值或默认值。**
**回归评估交给你信任的会话，本地模型负责接力，不再额外请一个模型当项目总审计。**

```text
人：目标 + PRD + 两个会话 + 停止阈值（例如 80%）
                         |
评估会话 A <-> 左脚踩右脚：本地模型协调 <-> 执行会话 B
核对 PRD        搬运结果、识别回复、交接提示词       执行任务
评估完成度      未达标继续，达标停止               返回结果
给收口计划及提示词
```

这里的 A、B 是角色，不是两个指定品牌，也不要求来自两个不同产品。
本地监督者替代的是反复协调的人，**不是替代评估会话重新打分、重新规划或改写任务**。

## 平时怎么用，项目就想怎么接手

下面描述的是**目标工作方式，不是已经可用的操作入口**。

你现在可能这样做：

1. 在执行会话 B 里让 Codex 或 ZCODE 完成一轮任务，拿到执行结果。
2. 复制结果到评估会话 A，再问：

   > 你帮我核对一下目前项目与 PRD 的进展，按百分比评估完成度，列出缺损项目，并给出下一轮收口计划及可以直接发送的提示词。

3. A 回复：“目前完成度 65%，还缺这些项目”，并给出提示词。
4. 把这条提示词复制回 B，让它继续执行。
5. B 再给执行结果，你再拿去问 A。如此往复，直到满足你定的停止条件。

左脚踩右脚要做的，就是在你授权后，由本地模型接替第 2 到第 5 步的日常协调。
它也应支持从目标和 PRD 开始，先向 A 请求第一轮评估和任务，不强制你先手工准备一条结构化消息。

### 80% 停止，具体是什么意思？

每次运行由你设置停止百分比，例如 60%、80% 或 95%；系统按“本轮完成度 >= 你设置的阈值”停止。
下表仅以“当前 PRD 范围完成度达到 80% 停止”为例：

| A 对同一目标的本轮评估 | 接下来做什么 |
| --- | --- |
| 65%，附缺项及下一轮提示词 | 把提示词交给 B，执行后再问 A |
| 77%，附下一轮提示词 | 继续交接，不要求你每轮复制或点批准 |
| 80% 或 83% | 停止新任务，即使 A 还附了下一轮提示词也不再发送 |
| 没给总完成度，或给出互相矛盾的数字 | 向 A 问清楚，不由本地模型猜一个百分比 |

这个百分比是**你选定的评估会话对目标完成情况的判断**，不是系统独立认证的客观成绩，
也不是测试通过率或“运行了几轮”。不要求你先给每条需求设计一套权重算法。
达到 80% 表示“按你的要求停止”，不表示整个项目已经 100% 完成或可以自动发布。

未达标时正常循环自动继续；你随时可以停止。权限请求、发送结果不明、连接故障，
或达到事先约定的时间/轮次上限时也会暂停，不会为了凑到 80% 无限跑。
信任评估能力不等于批准删除数据、发布或其他越权操作，必要的人类决定仍保留。

### 哪两个会话可以搭在一起？

| 你想用的组合 | 配置方式 |
| --- | --- |
| ChatGPT 网页 + Codex | 一个评估，一个执行 |
| Codex 同一项目下的两个会话 | 会话 A 核对 PRD，会话 B 推进任务 |
| Codex Work 或普通对话 + ZCODE | 按实际能力分配评估与执行角色 |
| 豆包或其他对话产品 + 执行会话 | 仍是同样的报告与提示词交接 |

**这些是需要支持的配置场景，不是已支持产品清单。** 网页、桌面或其他入口只是接入方式，
不是产品定义；执行侧需要实际能执行目标任务，纯聊天会话不能被假称为已修改代码。
同一产品也必须绑定两个不同的会话，不能串台或把消息发回自身。

### 多个项目，一起推进

正式入口会是桌面应用，不要求你一直守着命令行。Windows先做，再在Apple Silicon Mac上验证。
首批分别接你已有的Codex项目内两个会话、ZCODE项目内两个会话，不偷偷改成新的API聊天。

你可以登记多个项目文件夹，每个项目从已有会话中选一评估、一执行，分别设置目标和停止百分比。
例如项目甲设60%，项目乙设95%；两边都评到80%时，甲停、乙继续，不用共享一条停止线。
其他会话仍属于你的项目，但不会自动加入循环；多个执行会话同时改同一文件夹不在第一版范围。

后台等待可以并行，鼠标键盘不能分身。需要切窗口或输入时，系统在你开启的**专用自动操作模式**中排队操作，
明确显示正在控制哪个项目；非该模式不抢前台。你接管、焦点不对或身份不明就停止新输入。
你可暂停某个项目或全局停止；外部Agent是否真的停止会另外显示，不会把“不再发送”说成“全都停了”。

先用官方接口或系统控件读写，必要时在获准模式临时粘贴；第一版不靠截图/OCR点坐标。
Mac按需申请辅助功能权限，Windows不默认管理员运行；临时剪贴板不保证所有格式无损恢复，也不能覆盖你新复制的内容。
桌面壳不自动赋予控制权限，各应用的项目定位、完整读取和发送仍须实测。上述都是待实现的工作方式。

模型负责理解回复和交接，Adapter 负责按获准方式读取与发送，程序负责权限、限额和防重复发送。
不未经许可抢你的鼠标键盘，不静默换产品或换会话；接不通就说明缺什么，不用“理论上可以”冒充跑通。
现有评估工具只处理模拟材料，不会操作这些会话。

## 名字为什么这么离谱？

武侠和网络段子里，左脚踩右脚好像就能施展轻功。
现实物理不答应。两个 AI 互相递任务能不能把工作往前推？我们也不知道，准备试试。

工程上严肃，名字上不正经。项目第一步不是飞，是先把脚摆对。

## 现在怎么跑？

现在能跑的是**基础与评估工具测试**，不是自动协作。需要 Git、Node.js 24 和 npm。

```sh
git clone https://github.com/aiwindyjm/left-foot-on-right-foot.git
cd left-foot-on-right-foot
npm ci
npm test
npm run validate
```

验证检查协议样例、格式反例、状态定义、文档链接、原稿完整性和常见敏感信息。
不需要 API Key，不登录 ChatGPT，不控制浏览器或 Agent。
测试通过不表示自动闭环已经可用。

本机已有 Ollama 和固定模型时，可运行只读检查，不加载模型：

```sh
npm run eval:preflight
```

资源不足会明确停止，这是检查结果，不是模型成绩。实际推理需显式确认，命令与考题见 [评估说明](evaluation/README.md)。
当前调查结果和阻塞见 [Phase 1A 报告](docs/phase-1a-report.md)。
